- SERVICE: วันเวลารับบริการ, อาการสำคัญ, สัญญาณชีพ (BTEMP, SBP, DBP, PR, RR), น้ำหนัก ส่วนสูง

- DRUG_OPD: รหัสยา, ชื่อยา, จำนวน, หน่วย, ราคา/ต้นทุน
- PROCEDURE_OPD: รหัสหัตถการ (รวมหัตถการแผนไทย), ค่าบริการ
- PROVIDER: ผู้ประกอบวิชาชีพและประเภทวิชาชีพ
- ตาราง "ยา master": รหัสยา, ชื่อสามัญ, ATC (ถ้ามี), ความแรง (strength), รูปแบบยา, เส้นทางให้ยา

# เฟส 1: Functional Prototype (static web app, deploy บน GitHub Pages)

## เทคโนโลยี
- Vite + React + TypeScript + Tailwind CSS + Recharts build เป็น static ได้
- ตั้ง base path ของ Vite ให้ทำงานบน GitHub Pages และใช้ HashRouter
- ไม่มี backend จริงบน Pages แต่แยก adapter layer และสร้าง mock API server (Node/Express) ใน /api-mock สำหรับสาธิตการเรียก API

## โมดูล A: Smutthan Engine (เป้าหมาย 1)
- Input: เคสผู้ป่วย, อายุ, เพศ, สัญญาณชีพ, อาการ, โรคเรื้อรัง
- Context real-time: ดึงอากาศจาก Open-Meteo API (ฟรี ไม่ต้อง key) ด้วย fetch ฝั่ง client ตามพิกัด + วันเวลาปัจจุบัน map เป็น ฤตุสมุฏฐาน, กาลสมุฏฐาน, ประเทศสมุฏฐาน, อายุสมุฏฐาน, ธาตุสมุฏฐาน ตามตำราแพทย์แผนไทย (ระบุในเอกสารว่าเกณฑ์ต้องให้แพทย์แผนไทยตรวจสอบ)
- Process: rule-based scoring โปร่งใส คำนวณแนวโน้มความแปรปรวนของธาตุประธาน (ดิน น้ำ ลม ไฟ) พร้อมน้ำหนักและเหตุผลของแต่ละปัจจัย (explainable) rules แยกเป็น JSON แก้ได้โดยไม่แตะโค้ด
- Output: กราฟเรดาร์ 4 ธาตุ, ระดับแนวโน้ม, ปัจจัยหลัก, คำแนะนำเบื้องต้น, disclaimer
- หน้า "ความสอดคล้อง": เปรียบเทียบผล engine กับการ override ของแพทย์แต่ละคน (อัตราเห็นตรงกัน ความต่างรายธาตุ) ด้วยข้อมูลสังเคราะห์ เพื่อสื่อว่าลดความเหลื่อมล้ำได้
- GenAI (optional): อธิบายผลเป็นภาษาธรรมชาติ รับเฉพาะผล rule engine ที่ไม่มีข้อมูลระบุตัวตน ผ่าน prompt template ในไฟล์ มี fallback เป็นข้อความ template เมื่อไม่มี API key

## โมดูล B: สั่งยาแผนไทย (Thai Medicine Prescribing) + Herb-Drug Interaction (เป้าหมาย 2)
หน้านี้ต้องให้ความรู้สึกเหมือนแพทย์กำลังสั่งยาจริง:
1. แถบซ้าย "ยาที่ผู้ป่วยใช้อยู่": ยาแผนปัจจุบันพร้อมขนาดยา, โรคเรื้อรัง, ข้อมูลที่ต้องระวัง (อายุ, ตั้งครรภ์ถ้ามี) เห็นตลอดระหว่างสั่งยา
2. ช่องค้นหา "บัญชียาแผนไทย" (formulary): ค้นด้วยชื่อไทย ชื่อสามัญ รหัสยา หรือข้อบ่งใช้, กรองตามประเภท (ยาเดี่ยว/ตำรับ) และรูปแบบยา, แสดงป้ายสถานะในบัญชี
3. การ์ดข้อมูลยาเมื่อเลือก: รูปแบบ ความแรง ข้อบ่งใช้ ข้อห้าม ข้อควรระวัง ขนาดยามาตรฐาน
4. ฟอร์มสั่งยาต่อรายการ:
   - ขนาดต่อครั้ง (ค่าเริ่มต้นจากขนาดมาตรฐานตามอายุ/น้ำหนัก แพทย์แก้ได้)
   - ความถี่ (วันละกี่ครั้ง เช้า-กลางวัน-เย็น-ก่อนนอน) และเวลา (ก่อน/หลังอาหาร)
   - จำนวนวัน, จำนวนรวมที่จ่าย (คำนวณอัตโนมัติ), ขนาดรวมต่อวัน (คำนวณอัตโนมัติ)
   - วิธีใช้ (รับประทาน/ใช้ภายนอก/ประคบ), คำแนะนำพิเศษ, เหตุผลการสั่ง (เชื่อมกับการวินิจฉัย/ICD-10-TM)
5. ตรวจอัตโนมัติทันที: ขนาดเกินช่วงปกติหรือขนาดสูงสุดต่อวัน, ระยะเวลาเกินที่แนะนำ, ข้อห้าม/ข้อควรระวังตามอายุและภาวะ, ยาซ้ำซ้อน, อันตรกิริยากับยาแผนปัจจุบัน แสดงแถบเตือนตามระดับ (สูง/ปานกลาง/ต่ำ/ไม่มีข้อมูล) พร้อมกลไก คำแนะนำ source
6. ตะกร้า "ใบสั่งยา": รวมรายการที่สั่ง สรุปคำเตือนต่อรายการ ต้องกด "รับทราบ" หรือใส่เหตุผลเมื่อสั่งยาที่มีคำเตือนระดับสูง
7. ยืนยันใบสั่งยา: ตัวอย่างใบสั่งยา/ฉลากยา (ชื่อยา ขนาด วิธีใช้ คำเตือน) ส่งออก PDF/พิมพ์ และ JSON พร้อมรหัสยาสำหรับส่งเข้า HIS (ตาม config mapping ของ DRUG_OPD)

ฐานข้อมูลกลาง Herb-Drug Interaction:
- schema: herbs, drugs (ชื่อสามัญ/ATC/รหัสยา), interactions (คู่ยา, ระดับ, กลไก, คำแนะนำ, evidence level, source, ผู้ตรวจสอบ, วันที่ตรวจ, เวอร์ชัน)
- Interaction engine: normalize ชื่อ/รหัสยา, จับคู่ยาแผนปัจจุบันทุกตัวกับยาแผนไทยที่สั่ง, พิจารณาขนาดยาเมื่อมีข้อมูล
- หน้า admin demo "จัดการฐานข้อมูลกลาง": ดูรายการ ค้นหา กรองตามระดับ ดูประวัติเวอร์ชันและสถานะการตรวจสอบ
- API (openapi.yaml) และ mock ใน /api-mock:
  - POST /v1/interactions/check (รับยาปัจจุบัน + ใบสั่งยาแผนไทย ส่งผลปฏิกิริยาและคำเตือนขนาดยา)
  - GET /v1/formulary, GET /v1/herbs, GET /v1/drugs, GET /v1/interactions/{id}
  - POST /v1/prescriptions, POST /v1/assessments
  - ระบุ API key/OAuth2 ใน spec, audit log, เวอร์ชันฐานข้อมูล
- ตัวอย่าง payload สไตล์ FHIR (MedicationRequest) สำหรับ HIS ที่ส่งใบสั่งยาเข้ามาเช็ก

## โมดูล C: ICD-10-TM Real-time Analytics (เป้าหมาย 3)
- นำเข้า DRUG_OPD, PROCEDURE_OPD, DIAGNOSIS_OPD (สังเคราะห์) ประมวลผลเมื่อมีการบันทึกใหม่ (จำลอง real-time ด้วย event stream ในเบราว์เซอร์/mock server) รวมใบสั่งยาที่เพิ่งสั่งจากโมดูล B อัตโนมัติ
- แดชบอร์ด: จำนวนการจ่ายยาแผนไทยและหัตถการแยกตาม ICD-10-TM, ต้นทุน/ค่าบริการรวม, ต้นทุนต่อเคส/ต่อ episode, สัดส่วนยาแผนไทยต่อแผนปัจจุบัน, แนวโน้มรายเดือน
- มุมมองเศรษฐศาสตร์สาธารณสุข: cost per case/episode และโครงสำหรับต่อยอดเป็น CEA/CUA (ICER) เมื่อมีข้อมูลผลลัพธ์จริง ระบุชัดว่าเป็นข้อมูลสังเคราะห์ ห้ามสรุปว่าแผนไทยคุ้มค่ากว่าจากข้อมูลสังเคราะห์
- รายงานคุณภาพข้อมูล: ตรวจรหัส ICD-10-TM/รหัสหัตถการที่ว่างหรือไม่สอดคล้อง

## โมดูล D: Integration-ready
- /src/adapters มี interface: getPatient(), getVitals(), getMedications(), getProcedures(), getDiagnoses(), getFormulary(), savePrescription(), saveAssessment() มี mock adapter, 43-file adapter (อ่าน CSV ตาม config mapping) และ stub REST/FHIR adapter
- unit test: rule engine, interaction matcher, ตัวตรวจขนาดยา, mapper, analytics
- สคริปต์ตรวจ PII ก่อน commit

## Workflow หน้าจอ (ตามห้องตรวจจริง)
1. เลือกผู้ป่วย: สรุป อายุ เพศ โรคเรื้อรัง ยาแผนปัจจุบันพร้อมขนาดยา
2. ประเมินสมุฏฐาน: ฟอร์มสัญญาณชีพ/อาการ (ค่าเริ่มต้นจากประวัติ), แถบสภาพแวดล้อม real-time, ผลลัพธ์พร้อมเหตุผล, แพทย์ override ได้พร้อมบันทึกเหตุผล (human-in-the-loop)
3. สั่งยาแผนไทย: ตามโมดูล B
4. สรุปและบันทึก: สรุปการประเมิน ใบสั่งยา คำเตือนที่รับทราบ หัตถการ รหัส ICD-10-TM ส่งออก PDF และ JSON พร้อมช่อง feedback
5. แดชบอร์ดภาพรวม (ผู้บริหาร/นักวิชาการ): โมดูล C, หน้าความสอดคล้อง, หน้าสถานะระบบ

## ดีไซน์ (modern, clean, clinical-calm)
- ดูเป็นผลิตภัณฑ์ health-tech สมัยใหม่ ไม่ใช่เว็บราชการหรือ template ทั่วไป หลีกเลี่ยงกราเดียนต์ม่วง-ชมพูแบบ generic
- พาเลตต์โทนสมุนไพร: เขียวมรกต/teal เป็นสีหลัก พื้นหลังขาวอุ่น/เทาอ่อน accent ทอง/อำพัน สีธาตุ: ดิน=น้ำตาลอำพัน น้ำ=ฟ้า ลม=เขียวอมเทา ไฟ=ส้ม
- สีสถานะคำเตือน: สูง=แดง ปานกลาง=ส้ม ต่ำ=เหลือง ไม่มีข้อมูล=เทา ห้ามใช้แดงนอกเหนือคำเตือนสูง ไม่พึ่งสีอย่างเดียว ใช้ไอคอน+ข้อความกำกับ
- design tokens (CSS variables/Tailwind theme), มุมมน 12-16px, เงานุ่ม, spacing scale
- ฟอนต์ไทย: IBM Plex Sans Thai หรือ Noto Sans Thai + Sarabun พร้อม fallback
- Layout: sidebar ย่อ/ขยายได้ + top bar แสดงผู้ป่วยที่เลือกและสภาพอากาศปัจจุบัน เนื้อหาเป็นการ์ด ข้อมูลสำคัญอยู่ใน viewport แรก
- หน้าสั่งยาแบ่งสามส่วน: ยาที่ใช้อยู่ (ซ้าย), formulary และฟอร์มสั่งยา (กลาง), ใบสั่งยาและคำเตือน (ขวา) บนแท็บเล็ตพับเป็นแท็บ
- ส่วนประกอบ: stepper ขั้นตอนตรวจ, badge, tooltip อธิบายศัพท์, accordion เหตุผลของ engine, toast, dialog รับทราบคำเตือน
- Micro-interactions: transition นุ่ม, skeleton loader ตอนโหลดอากาศ, กราฟ animate, เคารพ prefers-reduced-motion
- Dark/light mode, responsive รองรับแท็บเล็ตและคอมพิวเตอร์ในห้องตรวจ ปุ่มกดใหญ่พอ
- Accessibility: contrast ผ่าน WCAG AA, keyboard navigation, aria-label, focus ring ชัด
- หน้า Landing สั้นๆ อธิบายคุณค่า 3 เป้าหมาย + ปุ่ม "เริ่มสาธิต"
- โหมดสาธิตเลือก 10 เคสได้ มีป้ายข้อมูลสังเคราะห์ทุกหน้า
- ศัพท์แพทย์แผนไทย (ธาตุทั้ง 4, สมุฏฐาน) เก็บไว้ในไฟล์ glossary เดียว
